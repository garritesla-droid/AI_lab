# Свежий публичный срез: запуск отдельного сервиса

В комплекте есть работающий Node.js-сервис без внешних библиотек. Он запускает новый обход восьми заданных официальных страниц при нажатии «Обновить публичную информацию». Это не универсальный поисковик: новые сайты добавляются в `service/sources.mjs`, а правила распознавания — в `service/collector.mjs`.

## Быстрая проверка на компьютере

Установите Node.js версии 22 или новее с https://nodejs.org/ . В папке распакованного сайта выполните `npm start`. Откройте http://127.0.0.1:8765/ . Страница и сервис работают вместе; `config.js` менять не нужно. Остановить: Ctrl+C. Проверки: `npm test`.

## GitHub Pages + отдельный публичный сервис

1. Загрузите всё содержимое архива в корень `AI_lab`, сохранив папки `service` и `tests`. GitHub Pages публикует интерфейс как прежде.
2. Создайте Node Web Service у выбранного хостинга, подключив этот репозиторий. Например, на Render: New → Web Service → выбрать репозиторий, среда Node, Build Command `npm install`, Start Command `npm start`. Требуется Node 22+. Условия и стоимость хостинга выбираются владельцем; автоматическая подписка не создаётся. Официальная инструкция: https://render.com/docs/deploy-node-express-app . Для другого провайдера также приложен Dockerfile.
3. В переменной окружения сервиса `ALLOWED_ORIGINS` укажите точный origin сайта, например `https://ВАШ-ЛОГИН.github.io` — без `/AI_lab/` и без завершающего слеша. Несколько разрешённых origin разделяются запятой. `PORT` обычно задаёт хостинг.
4. После запуска возьмите HTTPS-адрес сервиса. В корневом `config.js` задайте `window.FIVE_CARDS_API = 'https://адрес-сервиса';` и сохраните изменение в GitHub.
5. Откройте публичный сайт Pages и нажмите «Обновить публичную информацию». Появятся отдельные статусы источников и время проверки. `/health` на адресе сервиса возвращает проверку работоспособности.

В архиве нет уже арендованного или опубликованного сервиса. Пока он не размещён и не подключён, GitHub Pages показывает инструкцию подключения, а не поддельное успешное обновление. При открытии index.html через file:// сбор не работает. Можно опубликовать весь сайт на Node-хостинге вместо Pages: тогда API работает с того же origin, `config.js` остаётся пустым, но origin хостинга всё равно добавьте в `ALLOWED_ORIGINS`.

## Какие доказательства сохраняются

На каждый источник: точная HTTPS-ссылка, время попытки, статус загрузки, SHA-256 очищенного текста, фрагмент до 20 слов. Контрольная сумма показывает идентичность текста, но сама по себе не подтверждает юридическую силу или актуальность условий. У каждого найденного сведения — ссылка на источник. Срез можно скачать отдельно; он также добавляется в скачанный отчёт калькулятора.

Классы: упоминание названия; партнёр из явно обозначенного раздела; отдельная совместная карта; поддержка способа оплаты; общие правила. Простое упоминание не считается сотрудничеством. Страница банка и страница магазина проверяются отдельно, без выдуманного «двустороннего подтверждения». Показатель «до X%» остаётся рекламным значением и не превращается в гарантированную ставку.

## Границы автоматизации

Это первая версия сборщика заданных источников. Он не входит в приложения банков, не обходит защиту сайтов, не распознаёт произвольные PDF и не гарантирует полноту предложения. Ответ 200 с проверкой браузера не считается успешной загрузкой правил. Ошибки и изменения структуры показаны явно. Старый срез после ошибки не получает новую дату. Каждое обновление перечитывает источники; общий интервал между запусками 30 секунд, один сбор одновременно, до четырёх запросов параллельно, 12 секунд и 3 МБ на источник.

В этой версии ни один извлечённый набор условий не признан полным для автоматического банковского расчёта: неизвестны персональная доступность, лимиты, срок, способ оплаты или регион. Поэтому публичный срез НЕ подменяет демо-ставки. Калькулятор остаётся явно обозначенной ручной моделью. Это намеренно: превращение рекламного максимума в обещание годового дохода было бы неверным. Чтобы поддержать автоматическое применение конкретного продукта, нужен отдельный проверенный разбор всех его правил и тесты; одного совпадения слов недостаточно.

Сервис получает запрос без финансовых сумм, магазина или города пользователя. Пользовательские URL на сервер не передаются. Исходящие адреса фиксированы, перенаправления запрещены. CORS ограничен заданными origin, но не заменяет авторизацию; общий лимит снижает нагрузку, а для большого публичного трафика хостинг должен добавить собственное ограничение запросов. Логи хостинга могут содержать IP и другие технические данные.
