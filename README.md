# Пять карт — версия 3

Адаптивный калькулятор пяти зарплатных карт и отдельный сервис свежего публичного среза. Интерфейс на русском, без персональных данных в исходных файлах. index.html находится в корне.

## Что изменилось

- Лаконичный интерфейс: «Мои траты», «Сравнение», «Источники»; крупные поля, скрываемые настройки и карточки на смартфоне.
- Город, магазины, сервисы, топливо и способ оплаты участвуют в ручном сценарии расчёта.
- Кнопка обновления запускает свежий обход восьми официальных страниц через отдельный сервис.
- Ссылки на доказательства, время загрузки, статус и короткий фрагмент источника доступны в интерфейсе и скачиваемых отчётах.
- Упоминание, партнёрство, совместная карта и поддержка оплаты различаются. Неполные условия не превращаются в подтверждённую выгоду.

## Важно о степени готовности

Интерфейс и сервис реализованы и проверены локально. Сервис ещё НЕ опубликован в интернете и НЕ подключён к вашему GitHub Pages. Развёртывание описано в SERVICE.md. Только загрузки HTML на Pages недостаточно для серверного сбора.

Сборщик проверяет заданный реестр, а не весь интернет. В проверке 13.11.2026 из этой среды удалось прочитать 4 из 8 источников; недоступность остальных показана явно. Доступность с другого хостинга может отличаться. Ни один разобранный набор условий пока не достаточен для автоматического подтверждения годовой выгоды: ставки калькулятора остаются демонстрационными / вручную введёнными. Это ограничение явно показано на сайте.

## Локальный запуск

Установите Node.js 22 или новее: https://nodejs.org/

Из папки сайта: `node service/server.mjs` (либо `npm start`). Откройте http://127.0.0.1:8765/ . Для остановки Ctrl+C. Тесты: `node --test tests/*.test.mjs` (либо `npm test`). Установка сторонних пакетов не нужна.

Двойной щелчок по index.html позволяет пользоваться ручным калькулятором, но не запускать сбор публичных данных.

## GitHub Pages

1. Распакуйте архив. Загрузите СОДЕРЖИМОЕ, а не сам ZIP, в корень репозитория AI_lab. Сохраните структуру папок. Если там уже есть одноимённые файлы, предварительно сохраните старую версию.
2. Сохраните изменения в основной ветке, например main.
3. Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save.
4. Дождитесь публикации. Публичный адрес показан в Pages; обычно это https://ВАШ-ЛОГИН.github.io/AI_lab/ . Отправляйте людям этот адрес, а не ссылку на ZIP из чата.
5. Для работающего обновления разверните отдельный сервис по SERVICE.md и внесите его HTTPS-адрес в config.js.

Официальная инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Формулы ручного сценария

Расходы магазинов входят в общий месячный бюджет, а не прибавляются к нему. При совпадении города и способа оплаты применяется ставка магазина с его лимитом в течение указанного числа месяцев. Затем используется базовая ставка для карты, ноль для СБП / оплаты через сервис. Нераспределённые покупки — по базовой ставке. Начисления каждого месяца суммируются, ограничиваются общим лимитом банка и умножаются на долю реально используемых бонусов.

Проценты за год = постоянный средний остаток × ставка / 100. Обслуживание = плата × 12, если доход ниже порога бесплатности; иначе 0. Подписка вычитается за 12 месяцев. Итог = полезный кешбэк + проценты − обслуживание − подписка. Акции не продлеваются автоматически сверх введённого срока. Доход не увеличивает остаток автоматически. Налоги, капитализация, округление каждой покупки банком и не внесённые условия не моделируются. Общие категорийные лимиты между магазинами нужно распределить вручную.

Публичный срез прикладывается к аналитике отдельно и не является доказательством вымышленных тарифов. Пользовательские доказательства должны сопровождаться ссылкой на точные условия, датой и описанием. Общая страница банка — справка, не доказательство каждой цифры.

## Файлы

- index.html, styles.css, app.js, ui.js — интерфейс и ручная модель.
- snapshot.js, config.js — подключение публичного среза.
- service/ — сервер и реестр источников.
- tests/ — проверки правил сбора и расчёта.
- SERVICE.md — публикация сервиса, ограничения и защита.
- Dockerfile, package.json — запуск на Node-хостинге.
- .nojekyll — отключение Jekyll для Pages.

Все пути интерфейса относительные. Введённые суммы хранятся только в памяти вкладки; обновление не отправляет их сервису. Скачанный расчёт содержит ваши суммы. Хостинг и внешние страницы могут вести свои технические журналы. Регистрация, ключи банков и рекламные трекеры не используются.
